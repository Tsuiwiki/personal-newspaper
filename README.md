# 纸间 · 个人数字报纸

把订阅源收进一份**每天有限**的报纸：固定栏目与版式、读完为止、历史按原样保留。
单人本地运行，不需要注册，默认只监听回环地址，数据只存在本机 SQLite 里。

当前进度：**Phase 0 + 1 + 2 + 3 + 4 + 正文提取**（工程骨架、安全基线、报纸与文章页、来源 CRUD、
RSS/Atom 采集与去重、手动收录、模板编辑器、期刊生成器与历史快照、文章库分页筛选与笔记、
应用内定时任务与设置页、补一期、在线备份、公开页面正文提取与手动正文导入）。
AI 摘要还没做，界面上对应的入口是明确的占位说明，不会假装能用。

## 快速开始

需要 Node.js **20.18 或更高**（本机 v20.18.0 实测），npm 10+。

```bash
npm install          # 安装 workspace 依赖
npm run db:seed      # 建库 + 迁移 + 写入示例数据（18 篇、1 期）
npm run dev          # 同时起后端与前端
```

打开 <http://127.0.0.1:5173>。后端在 <http://127.0.0.1:8787>，健康检查 `GET /api/health`。

想改端口或数据库位置，复制 `.env.example` 为 `.env` 再改；`.env` 不进版本库。

### 常用脚本

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 并行起后端（tsx watch）和前端（Vite） |
| `npm run dev:server` / `npm run dev:web` | 只起其中一个 |
| `npm run db:seed` | 建库、跑迁移、写示例数据；已有期刊时跳过，不覆盖你的数据 |
| `npm test` | 后端测试（SSRF、API 契约、Feed 解析、去重、采集、正文提取、模板与编排、定时任务与时区，共 72 个用例） |
| `npm run typecheck` | 后端 `tsc --noEmit` + 前端 `vue-tsc --noEmit` |
| `npm run build` | 构建前端静态产物到 `apps/web/dist` |
| `npm run build:site` | 导出只读站点到 `dist-site`（见下） |

### 导出只读站点

`npm run build:site` 读本机数据库，把**已出版**的期次连同版面快照、已保存正文导出成一个独立的静态站点
（`dist-site`）：不调用 `/api`，也没有采集、编辑和笔记入口。导出走字段白名单，阅读记录、笔记、订阅令牌
和数据库文件都不会进产物。

挂在子路径下（例如 GitHub Pages 项目站点 `/<仓库名>/`）时用 `PAPER_SITE_BASE=/<仓库名>/` 指定前缀，
资源地址与站内插图会跟着前缀走。本站点的线上版本就是 `gh-pages` 分支上的导出产物。

### 版本为什么钉死

本机 Node 20.18.0 下上不去最新版，以下三项是实测过的选择，升级 Node 后可再放开：

- `vite@5.4.21`：Vite 6/7 要求 Node ≥ 20.19
- `better-sqlite3@11.10.0`：12.x 起只有 Node 22 预编译包，本机没有 VS 编译工具链
- 不用 `concurrently`：它 10.x 要求 Node ≥ 22，改用零依赖的 `scripts/dev.mjs`

## 数据、备份与恢复

- 数据库默认在 `data/newspaper.db`，WAL 模式。
- **升级前自动备份**：迁移器发现有待执行迁移时，先 `db.backup()` 到 `data/backups/`，再在事务里逐条执行迁移。
- **在线备份**：设置页的「立即备份」调用 `db.backup()`，不用停服务，生成
  `data/backups/newspaper-backup-<时间戳>.db`，并列出目录里已有的备份（手动 / 升级前）。
- 也可以用命令行（任选其一）：
  - 停掉服务后直接复制 `data/newspaper.db`；
  - 服务运行中：`sqlite3 data/newspaper.db "VACUUM INTO 'data/backups/manual-20261028.db'"`
    （本机没装 sqlite3 CLI 时用第一种）
- 恢复：停服务 → 把备份文件复制成 `data/newspaper.db` → 删掉同目录的
  `newspaper.db-wal` / `newspaper.db-shm` → 启动。恢复没有界面按钮，故意留成手动步骤。
- 迁移文件只增不改。改动历史迁移会让老库与代码不一致，需要写新的迁移来修正。

## 安全基线（已落地）

| 项 | 做法 |
| --- | --- |
| SSRF | 只允许 http/https、无内嵌凭据、端口 80/443；域名解析后逐个校验，命中回环/私网/链路本地/保留地址即拒绝 |
| DNS 重绑定 | 校验通过后把解析结果**钉住**，连接时用固定 IP，不让 socket 再解析一次 |
| 跳转 | 手动跟随，最多 3 跳，**每一跳都重新校验** |
| 拉取限额 | 超时 15s、响应体上限 2MB、跳转上限 3；单个 Feed 最多解析 300 条；批量采集最多 3 个来源并发 |
| 正文提取 | 只读公开 HTML；复用同一套 SSRF/跳转校验，超时 12s、上限 3MB；不执行脚本、不带 Cookie，401/403/429 一律停下 |
| 条件请求 | 保存 `ETag` / `Last-Modified`，命中 304 不重复解析入库 |
| 去重 | 同来源按 `guid`/`id`，全局按 canonical URL 与标题+摘要指纹；标题本身不参与判重 |
| 本机服务防打洞 | 绑定回环时校验 `Host` 头；写操作校验 `Origin`，只放行 5173 的开发源 |
| 日志 | 结构化 JSON 单行，敏感键（cookie/authorization/token/password…）自动打码，长文本截断 |
| 密钥 | 只从环境变量读；前端产物里没有任何密钥 |

`apps/server/test/url-guard.test.ts` 覆盖地址判定、协议/端口拒绝、跳转拦截、体积与超时上限；
`apps/server/test/api.test.ts` 覆盖健康检查、期刊、文章分页/来源/关键词筛选、笔记读写、校验失败、

`apps/server/test/feed-parser.test.ts` 与 `ingest.test.ts` 覆盖三种 Feed 格式、实体解码、URL 规范化与去重矩阵；
`sources-api.test.ts` 用本机 HTTP 服务器跑完整流程：新增、重复、坏 Feed、304、停用、单源失败隔离、

## 采集与来源页

来源页现在可以：添加订阅（先抓一次再落库）、验证地址、立即采集、启停、删除，手动粘贴链接收录，
以及按来源开关「自动提取」正文。采集默认只保存标题、摘要、作者、封面图和链接，
不绕过登录或付费墙；正文提取默认关闭。

- 单次最多 300 条，15 秒超时、2MB 上限；命中 ETag/Last-Modified 就跳过解析。
- 开启自动提取的来源，在本次采集新入库的文章里最多读 3 篇原文；单篇失败只写原因，不影响采集。
- 每个来源独立记录 `last_status` / `last_error`；失败不会删除已有文章。
- 「全部采集」只跑启用的来源，最多 3 个并发，返回每个来源的结果与合计。
- 删除来源只删配置，文章留在文章库和往期报纸里。
- 定时采集在设置页开启，默认每天 07:00（按设置时区）；也可以随时手动「全部采集」或「立即运行一次」。

## 文章库与笔记

文章库是采集内容的全集，未编进报纸的文章也留在这里，不会因为容量上限被丢掉。

- 按阅读状态（未读 / 稍后读 / 已读）、来源筛选，标题或摘要关键词搜索，可组合使用。
- 服务端分页，每页 20 篇；筛选只影响查询，不会改动文章或阅读状态。
- 每篇文章的阅读页可以写一条笔记（最多 4000 字），保存后存进本机 `reading_states`；清空内容即删除笔记。
- 笔记和阅读状态互相独立：改状态不会覆盖笔记，存笔记也不会把状态改回未读。
- 笔记只存在本机，不参与采集、不进入报纸版面，也不会同步到任何地方。

## 正文提取与手动正文

- **入口**：文章页的「提取正文」按钮随时可用；来源页的「自动提取」只影响之后采集到的新文章。
- **只读公开页面**：复用采集的 SSRF 守卫，不执行 JavaScript、不带 Cookie；遇到 401/403、429、
  非 HTML、正文过短都按失败处理，保留标题、摘要和原文链接，不绕过任何访问限制。
- **提取方式**：先用 Readability 找文章主体，读不到时退回 `article` / `main` 等主区块兜底；
  只保存纯文本，不落 HTML；页面标题、h1 与文章标题不一致时，也会去掉正文开头重复的标题行；
  单篇上限 6 万字，超长会截断并在页面上提示。
- **写入门槛**：正文至少 280 字才写入，避免把导航和版权声明当成正文；成功后标记 `extracted`。
- **手动正文**：正文没抓到或你想保存自己的版本时，可在文章页粘贴正文，标记为 `user_provided`；
  之后提取接口返回 409，绝不会覆盖你提供的内容。手动正文上限 20 万字符。
- **失败可回看**：文章上会保留最后一次提取失败的原因；重新提取成功或被手动正文替换后清空。

## 模板与期刊生成

模板编辑器在 `/templates`：改刊名、主题色、纸面质感、字号与行距、正文宽度、每期总容量，以及每个栏目的
版式、条数上限、时间窗、排序规则和来源范围。来源勾选顺序就是 `source_priority` 的优先顺序；右侧的
「版式示意」只用占位骨架，**不是实际文章**。模板保存后，已出的报纸不受影响——每期都存了自己的
`template_snapshot_json`。

今日报纸页的流程是 **预览 → 草稿 → 出版**，任何一步都不会悄悄改历史：

- **预览不写库**：点「生成预览」只按当前模板和候选池算一遍，告诉你哪几篇会入选、哪几篇被容量挤掉。
- **候选规则**：启用来源的文章，或手动收录（`source_id` 为空）的文章；落在时间窗内（栏目 `maxAgeDays`
  优先，默认 7 天，按设置时区的当地零点起算）；没有被**任何其它一期**用过。同一篇文章不会在
  两期里重复出现。
- **容量**：先按栏目顺序分配，每栏受自己的条数上限约束，全局再受模板的每期容量约束；栏目顺序就是优先级。
- **保存**：默认存成 `draft`。同一天已有草稿时要显式替换（预览面板会提示），已出版的期次**不可覆盖**，
  接口返回 409。
- **空候选不硬凑**：候选池为空时返回 `generated:false` 并说明原因（没有新文章 / 都被用过 / 被来源与时间
  筛选挡掉），不会生成一张空报纸，也不会拿旧文章冒充今天。
- **出版**：草稿确认后点「出版」转成 `published`。此后期次内容固定，只有另起一天才能生成新的。

取消勾选/停用来源只影响**以后**的生成；删除来源也不会动已经排进往期报纸的文章。

## 定时任务与设置

`/settings` 是运行时配置入口，值存在本机 `app_settings` 表的 `schedule` 键里（JSON），不进环境变量。
`.env` 的 `TZ` 只作为新库的默认时区，之后以界面里的设置为准。

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 启用每日定时任务 | 开 | 关掉只停自动运行，手动「立即运行一次」仍可用 |
| 每天几点开始 | `07:00` | 按设置时区的当地时间，24 小时制 |
| 时区 | `.env` 的 `TZ`（默认 `Asia/Shanghai`） | IANA 名称；决定采集时刻、期刊的「今天」和时间窗零点 |
| 采集完成后自动编排一期 | 开 | 关掉只采集，不排报纸 |
| 生成后直接出版 | 关 | 关着只生成预览稿，确认版面后再发布 |

运行方式：

- 应用内调度器每 30 秒检查一次，**不依赖系统 cron**；后端进程必须开着，退出期间不会补跑。
- 每天最多一条成功的定时运行记录，由 `job_runs` 的唯一索引保证；重启进程不会把同一天再跑一遍。
  失败记录不占当天名额，冷却后会重试。
- 启动时如果今天已过采集时刻且还没跑过，会立即补跑；上次进程留下的 `running` 记录会被标为失败并写明原因。
- 每个启用的来源采集一次；失败的来源在 1.5 秒后重试一次，仍失败只记在本次任务里，其它来源照常入库。
- 整轮任务失败（例如数据库异常）会在 10 分钟后重试，不会每 30 秒撞一次。
- 定时任务**不会覆盖已有草稿**，也不会动已出版的期次；要替换草稿请在今日报纸页或「补一期」里手动确认。
- 任务状态是 `ok`（全部成功）、`partial`（有来源失败，或因草稿/已出版而跳过生成）、`failed`（整轮失败）；
  执行中为 `running`。`skipped` 是保留状态，目前没有产生。

设置页还能：

- 看调度器状态、下次运行时间、设置时区的当前日期与时间、今天是否跑过，以及最近几次运行记录
  （触发方式、状态、每个来源的成功/失败/新增数、生成结果和原因）。
- 「立即运行一次」：手动跑一轮与定时相同的流程，与定时任务共用同一把锁；已有任务在跑时返回 409。
- 「补一期」：默认填昨天的日期，先预览再保存；可以存成预览稿或直接出版，已有草稿会替换，已出版的日期拒绝覆盖。
- 「立即备份」：在线 `db.backup()` 到 `data/backups/`，并列出目录里已有的备份（手动 / 升级前自动）。

## 示例数据说明

`npm run db:seed` 写入 5 个来源（含一个采集失败、一个手动停用）、1 套「古典头条」模板（5 个栏目，五种版式）、
18 篇文章（其中 2 篇带完整正文，1 张图片故意失效用于检验降级），以及 2 篇已读、1 篇稍后读的阅读状态。
示例中的「本期」日期取 Asia/Shanghai 的当天，方便直接把首页当成今天的报纸看。

## 已知限制

- 定时任务跑在服务进程内，没有系统级守护：关掉服务或关机期间不会补跑，开机后只判断「今天」，
  不会按天回放错过的日期。
- 调度精度是 30 秒，所有启用的来源在同一时刻采集；`poll_interval_minutes` 仍只存配置，
  没有按来源的独立轮询。
- 同一天只保留一期：可以替换草稿，但已经出版的当天期次不能改，也不能在同一天再出一版。
- 生成后不能在界面上手动换稿或重排文章：想调整就改模板再替换草稿；`manual` 排序（置顶指定文章）
  目前只有接口支持，界面上还没做。
- 采集只支持 RSS 2.0 / RSS 1.0 / Atom；`webpage` 类型还没有接入独立的网页订阅流程。
- 正文提取是启发式结果：不执行 JavaScript，不保证完整；自动提取每次采集最多 3 篇，
  失败后不会自动重试，也没有按站点实现 robots.txt 协商或独立限速。
- 页面需要登录、验证码或付费墙时直接失败，不会尝试绕过。
- 单个 Feed 每次最多读 300 条，不保证回补更早的历史文章。
- 文章库可以筛选与搜索，但还不能按笔记筛选，也没有批量操作。
- 备份可以在界面里在线生成，但恢复必须手动停服务、替换数据库文件；没有一键恢复按钮。
- 图片走浏览器直连原站，不经过本地代理；失效时降级为占位框，不影响阅读。
